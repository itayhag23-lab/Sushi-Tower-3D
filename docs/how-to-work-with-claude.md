# איך למקסם את Claude Code — מדריך מעשי

## העיקרון
Claude לא "יודע" מה אתה רוצה. הוא מייצר את הדבר הממוצע והבטוח אלא אם נותנים לו **הקשר, כיוון עיצובי, וקריטריון סיום**.
מי שמוציא אתרים יפים לא כותב פרומפטים טובים יותר — הוא בנה סביבה שבה גם פרומפט בינוני נותן פלט טוב.

## שלוש השכבות (מהחזקה לחלשה)

### 1. CLAUDE.md — הזיכרון הקבוע
קובץ בשורש הפרויקט שנקרא אוטומטית בכל שיחה. כאן שמים חוקי עיצוב, סטאק, ואיך לדבר איתך.
כבר קיים בפרויקט הזה. מעדכנים אותו בכל פעם שצריך לתקן אותי פעמיים על אותו דבר.

### 2. Skills — מומחיות לפי משימה
תיקייה `.claude/skills/<שם>/SKILL.md`. נטענת רק כשרלוונטי, ולכן אפשר להכניס בה הרבה פירוט.
כאן קיימת `beautiful-ui`. קוראים לה כך:
```
/beautiful-ui תעצב מחדש את מסך הפתיחה
```

### 3. הפרומפט עצמו
כאן רק מה שמשתנה: מה בונים עכשיו, ואיך זה נראה כשזה גמור.

## תבנית פרומפט שעובדת
```
מטרה: <מה המשתמש אמור להרגיש/לעשות>
מסך/קובץ: <איפה>
כיוון: <mood + הפניה לסגנון, למשל "כמו Apple Arcade, יפני מינימליסטי">
חובה: <3 דרישות קשיחות>
גמור כאשר: <קריטריון שאפשר לבדוק>
```
דוגמה:
```
מטרה: שחקן חדש יבין תוך 2 שניות מה עושים ויילחץ Play.
מסך: מסך פתיחה ב-SushiTower3D.jsx
כיוון: יפני מינימליסטי, אינדיגו + אלמוג, פונט Outfit.
חובה: לוגו אנימטיבי, כפתור ראשי אחד, שיא אישי.
גמור כאשר: עובד ב-375px, build עובר, ואין צבע קשיח מחוץ לטוקנים.
```

## שגרת עבודה מומלצת
1. משנים דבר אחד בכל פעם, לא חמישה.
2. מבקשים תכנית לפני שינוי גדול.
3. אחרי כל שינוי: הרצה + מבט בעיניים, לא רק "עבר build".
4. מה שיצא טוב — מקבעים ב-CLAUDE.md או ב-Skill.
5. מה שיצא רע פעמיים — כותבים כחוק, לא מתקנים ידנית שוב.
